# Ma trận field / nguồn sự thật / kiểm soát

Phạm vi: **24 bảng, 182 cột vật lý**, trích từ schema 001 và migration 007/010/011. Bản JSON: `field-matrix.json`; DDL gốc: `schema-inventory.json`.
Đây là kiểm kê mã nguồn, **không phải báo cáo quét database thật**. DDL và các ràng buộc SQL chưa được chạy trong môi trường này.

## Cách đọc
- A: sự thật khách quan (hãng/model/thông số/mã sản phẩm). B: hồ sơ/thực tế cửa hàng. C: định danh, trạng thái, metadata nội bộ.
- UI = Swing; BE = backend/service; SQL = kiểu/ràng buộc trong script. Ràng buộc đúng cấu trúc không chứng minh nguồn sự thật.
- Khóa ngoại/UNIQUE/CHECK tổng hợp còn nằm trong SQL gốc; kiểu trong bảng dưới là định nghĩa cột, không liệt kê lặp mọi index.
- Giao dịch mới cần sản phẩm/brand/category active+VERIFIED, barcode có giá trị phải VERIFIED; IsDemo phải khớp mode.
- Phone, tên/người liên hệ, địa chỉ, serial và nội dung bảo hành không được dùng dữ liệu thật của người khác làm demo.

## DTO, API và cell suy ra (không tạo thêm bảng DB)

| Thành phần | Nguồn / cách đối chiếu |
|---|---|
| `Item` | Products + Brands + Categories + Stock(KHO/QUAY). `warehouseQuantity`/`counterQuantity` là B suy ra; `category`/`brand` là A từ lookup, không tự gán theo tên. |
| `InventoryRequest` | UUID C; productId C; quantity/serials/reference/vendorId/unitCost/from/to là yêu cầu nghiệp vụ B; identifierType C. Backend kiểm tra lại với product, kho/quầy và mode. |
| `ItemQuantity` / `SaleRequest` | Giỏ là nháp. Product/giá/quyền/khuyến mãi được server kiểm tra; UUID/hash C; không ghi doanh thu khi chưa commit. |
| `Sale` | Snapshot hóa đơn và dòng, không join giá/tên mới để ghi đè lịch sử. |
| `ApiSession` | token/expiry/auth C, name/employeeId/role từ xác thực; token không log/xuất/bàn giao. |
| Báo cáo doanh thu/bán chạy | Tổng hợp từ hóa đơn B, ngày lọc và tên cột đúng query; chưa có doanh thu hoàn/hủy đã ghi sổ. |
| RowsPanel / CSV / bản in | Chỉ format ngày/enum theo loại cột; SKU/Model/Name giữ nguyên; tiền sắp xếp theo số; kèm mode. |
